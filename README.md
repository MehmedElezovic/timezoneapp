# Noon

Every client's pages in one place: the copy and the design of each page, version by version, reviewed together, plus your team's hours across timezones. One static app.

Tasks and the calendar are parked for now (`FEAT` in `js/core.js`): their code and data are kept, they just do not show. Flip `FEAT.tasks` or `FEAT.calendar` to `true` to bring one back.

## Files

- `index.html` — the shell: a narrow icon rail (Projects, Team, Settings, plus Tasks and Calendar when they are switched on; details on hover or click), the views, inbox, event panel, dialogs.
- `css/app.css` — styles. Dark frame and sidebar, white working panel, pastel event colours; dark theme via `data-theme`.
- `js/tz.js` — timezone data and search (cities, countries, codes like CET, offsets like UTC+2).
- `js/core.js` — time math, state (`localStorage` key `noon.v1`), availability (status, free windows, warnings), tasks, inbox, calendar links.
- `js/app.js` — everything on screen. The calendar week is one row per day with the hours across; overlapping things stack into lanes, the visible hours follow your online block and what is booked (at least 72px an hour, anything outside shows as an "earlier"/"later" marker), the day view is that row plus the day as a list with the free stretches you can book, and the month is a grid. The date strip above the grid is the only navigator (chevrons at its ends, Today caption on today's card, a quiet Today button only when today is off screen). Tasks (2026-11-12) is one plain list: each row shows who the task is for, high priority first and then the soonest due, with filters for open, due, high priority and done and one for a person. Assigning someone to a page (its Assigned to) gives them a task named after the page and due on its deadline (`pageTaskAdd`); taking them off removes it unless someone added to it. Whoever makes a task picks who can see it: everyone, only them and the people it is for, or everyone except some people; the people it is for always see it (`tasks.private` / `hidden_from`, enforced in the database by `task_visible`, `supabase/2026-11-12-hidden-tasks.sql`). Steps from a page's template (`FEAT.flows`, parked) stay out of it.
- `js/projects.js` — Projects: a project is a stack of versions. Every HTML file you upload is the next version (v1, v2, …), a new version starts with no comments. Open a version at desktop, tablet or phone width and click anywhere on the page to pin a comment to that element (replies, resolve, make a task). Compare with… on any version opens it on one side with the other side empty; pick any version for it, close either side and pick another, in either order. Both sides scroll together, and for each comment on the lower version it tells you how the higher one answers it (text changed with before/after, looks different, unchanged, element gone); click one to jump both frames to that spot, resolve it on the lower version or carry it to the higher one. Comments only ever carry upward, never to a lower version. Files (pages and the images, styles and scripts dropped with them) live in IndexedDB (`noon-files`); a lone HTML file reuses the previous version's files. The project list and comments ride on the team like tasks do; signed-in teams sync them to Supabase (rows in `projects`, `versions`, `version_comments`, `version_replies`, files in the private `project-files` bucket under `<team>/<project>/<version>/<path>`). Each version can be downloaded again, as the HTML file or as a zip with the files that came with it.
- The Tasks page (`renderTasks` in `js/app.js`) has one filter bar: My tasks or All tasks, then Open, Due, High priority, Projects or Done, then a project and a person. New task opens its own form. High priority is `t.pri`, set with the flag on any task. Steps that are not up yet show quietly under Coming up, and only reach the inbox and calendar when it is their turn.
- `js/folders.js` — Clients and folders. A client is a top-level folder, folders nest inside it, and a page (a project, with its design versions and soon its copy) sits in one of them, or under Not in a client until someone moves it. A client's More menu renames it, puts everything in it into a new folder (the client stays on top), moves it, or deletes it; deleting never deletes pages (a client's pages go to Not in a client, a folder's move up a level). Clients and pages carry categories from the team's lists, edited in Settings › Categories or added while tagging: for clients Audience and Industry, for pages Page type and Style to start with. A page opens on two tabs, Copy and Design; Design is the versions list described above. Signed-in teams keep them in `folders`, `categories` and `projects.folder_id` / `projects.cats` (`supabase/2026-11-10-clients-folders.sql`). The home and folder views list clients, folders and pages as short rows in one panel each, with a search over names at any depth, category filters (a page counts as its client's categories too, so B2B + Advertorial finds every B2B advertorial) and an order (last change or name); "Not in a client yet" folds away.
- `js/copy.js` — Copy, the page's first tab. A page's top (name, place, categories, deadline, people, the Copy and Design tabs: `pageChrome` in projects.js) stays put; under the tabs each tab shows its list of versions, and opening one shows it right there: the copy as a document, or the design in the viewer. Copy is a stack of versions like the design: write one in the editor (Quill, loaded on first use, with Noon's own toolbar: three heading sizes, bold, italic, underline, highlight, links, lists, quotes and a line between sections), paste it from Google Docs, Notion or Markdown, or upload a Markdown, Word (.docx, read by mammoth), text or HTML file. Whatever comes in goes through `cleanCopy`, which keeps only those formats, so the Markdown that comes out (`htmlToMd`: Copy as Markdown, Download as Markdown) is always valid: bold that would break Markdown's rules goes out as `<strong>`, and hand-written Markdown with broken bold (`**word **`) is repaired on the way in (`mdRepair`). Compare puts any two copy versions side by side, each as it reads, the two columns scrolling together; the red and green of struck and suggested words belong to suggestions inside one version. A saved version never changes, so comments sit on its text by character position: select words to comment, or to suggest other wording, which shows inline as struck words and new ones. The team accepts or declines a suggestion; accepted wording goes into the next version when someone edits it, and the suggestion then shows which version took it. A version being written is kept on this device as a draft until it is saved. Any copy or design version can be marked final. Signed-in teams keep copy in `copy_versions`, `copy_comments` and `copy_replies`, and the final marks in `projects.final_copy` / `final_design` (`supabase/2026-11-10-copy.sql`).
- `js/ads.js` — Ads, the page's third tab: static ad images (usually AI-made) that the team approves or rejects. Images come in as batches (each upload is the next batch); on the way in the browser makes two light copies of every image (`adCopy`: a review copy of 2000px at most and a 480px thumbnail, WebP, or JPEG where the browser cannot write WebP), so the grid and the viewer never load the full-size files. Each ad keeps three files, `<team>/<page>/ads/<ad>/thumb|review|original.*` in `project-files`. The grid has Approve and Reject on every card; opening an ad shows it under the tabs with comments pinned to a spot on it (or on the whole ad), and Approve or Reject there moves on to the next ad (← and → step through). Download approved packs the originals into a zip; Remove full-size files of rejected ads deletes those originals and keeps the review copy, the decision and the comments. Signed-in teams keep ads in `ads`, `ad_comments` and `ad_replies` (`supabase/2026-11-11-ads.sql`, which also lets project-files take files up to 50 MB).
- `js/flows.js` — Templates and steps. A project is a checklist: stages, each with steps, each step with one person, and steps happen in order from top to bottom. A template (Projects › Templates) is that same list ready to reuse, with questions asked when a project starts; a number question can repeat a step once per page and a yes/no question can switch a step on or off. Starting a project copies the template (`p.flow`), so changing a template never touches running work. Steps are ordinary tasks with `t.pj`, `t.ver` and `t.fl` (stage, place, `with` for same time as the step above); `flowChain` works out what each waits on from the order, and a step stays out of Tasks, the inbox and the calendar until it is its turn (`tkLocked` in core.js). `p.log` keeps what happened, who did it and when (`project_events`), for reading the history back later.
- `js/files.js` — Files on tasks, in the private `task-files` bucket under `<team>/<task>/<file>`, 10 MB each. Attach from a step's paperclip, by dropping a file on a step or an open task, or in the task panel and the New task form. Opening one shows it in the app: Markdown as a document (everything escaped first), an HTML page in a sandboxed frame that cannot reach the app, images, PDFs and video as themselves. An HTML file on a project's step can become that project's next version.
- `js/welcome.js` — the first run after signing in: name, timezone and hours, then a team and its invite link. Someone who came through an invite skips the team: their account starts in no team, and the invite waits in their inbox until they accept or decline it. It shows once per account (`profiles.prefs.onboarded`).
- `js/sync.js` — accounts and sync with Supabase. Noon needs an account: signed out, it shows the sign-in screen (email and password, an emailed link, or Google once that provider is on in Supabase). Teams mirror to the database, projects included, with the client-link fields and the element snapshot on each comment.
- `js/share.js` — review links, one per design or copy version (people other than clients use them too). A copy link opens the copy as a document, where the guest comments and suggests wording through the `copy_share_*` functions; accepting stays with the team. Share, on a version, turns on a link (`?share=<token>`). Whoever opens it gets that one version and nothing else: the page, the comments on the link, and their own comments and replies under a name they type, with no account. The app boots in a sandbox for it (nothing saved in that browser's Noon), and every read and write goes through the `share_*` functions in Supabase, which check the link each time. Comments come in two layers: the team's, in the app, and the client link's. Anyone on the link sees only the link's layer, whoever left it (a teammate who opens the link comments there too); in the app each version's comments have a Team / Client link switch, and posting or replying in Client link is visible on the link. Numbers count per layer. Turning the link off, or making a new one, stops the old link at once.
- `js/connector.js` — Settings › Claude: personal keys for the Claude connector. A key is shown once; only its SHA-256 is stored (`api_tokens`).
- `supabase/functions/noon-mcp/index.ts` — the Claude connector, a remote MCP server deployed as the Supabase Edge Function `noon-mcp` (`https://boielhshrswqdqkxiupz.supabase.co/functions/v1/noon-mcp`, JWT check off: it checks the Noon key itself). A page is a "project" in its tools. Tools: `list_clients` (clients, folders, category lists), `find_pages` (by category, client, name, final copy or design; a client's categories count for its pages), `get_copy` (a copy version as Markdown with its comments and suggestions; version "final"), `get_page_history` (every copy and design version with what became of each comment and suggestion), `upload_copy_version` (Markdown in; accepted wording found in it is marked as gone into it; optional resolve + reply), `list_projects`, `get_project`, `get_version` (full HTML, files, comments with selector, element snapshot and width, team comments as #1, #2 and review-link comments as C1, C2), `get_comments`, `upload_version` (next version, previous files carried over, optional resolve + reply), `resolve_comments` and `reply_to_comment` (`part: "copy"` for copy comments). `markdown.js` turns a copy version into Markdown with the app's rules (read with linkedom). Optional secret `NOON_APP_URL` adds links back into the app.
- `supabase/schema.sql` — the database schema, the migrations folded in. `supabase/2026-10-27-event-location-kind.sql` (place and kind on a meeting) and `supabase/2026-10-27-projects.sql` (projects, versions, comments, replies, the `project-files` bucket) are applied to the Timezoneapp project, and so are `supabase/2026-10-27-share-and-connector.sql` (client links, guest comment functions, the shared-file read rule, `api_tokens`) `supabase/2026-10-27-comment-layers.sql` (`version_comments.layer`: team or client, and the link functions limited to the client layer) and `supabase/2026-10-28-version-links.sql` (the link moves to `versions.share_on/share_token`, the link functions see only that version, and only its files are readable). `supabase/2026-10-28-team-requests.sql` (an invite link or an email seat becomes a request in `team_invites`, answered with `invite_answer`; pasting a link in Settings still joins at once) is applied too. `supabase/2026-11-03-flows.sql` adds templates (`flows`), `project_events`, and `project_id`, `version_id`, `flow` and `priority` on tasks. The app checks for the tables at sign-in and works without them.
- `legacy/noon-v1.html` — the previous single-file build, kept for reference.
- `ref/` — the design reference and preview captures.

## Run locally

Any static server works, for example:

    python -m http.server 4380

Address hooks, handy for screenshots: `?view=team|tasks|projects|calendar`, `?proj=first` opens the first project (or `?proj=<id>&ver=<n>` any project, which is what the link button in a project copies), `&ver=first|last` a version in the viewer, `&mode=compare` the side-by-side, `?cal=week|month|day`, `?theme=dark`, `?pop=new`, `?task=first`, `?inbox=1`, `?dlg=settings|member|auth|invite`.
